Design improvement report

Eight decisions, and why

Common problem

Dashboards full of charts; users hunt for what needs them.

Change

Home leads with “Needs your decision”, each with Approve inline. Four stats only.

Effect

The most frequent job (approve) takes 1 click from login. No workflow change.

Common problem

16 trip statuses shown raw confuse users.

Change

Statuses kept in data; UI groups them into 7 stages and 5 colour tones.

Effect

Users see “where is it” at a glance. BRD statuses unchanged.

Common problem

Separate “quotes” and “award” screens.

Change

Trip detail shows one task panel for the current stage: compare, pick a row, award.

Effect

No navigation between screens to finish a stage.

Common problem

Recommendation without reasons isn't trusted.

Change

Every recommendation shows the score inputs and one sentence on why, plus the cheapest alternative.

Effect

Meets BRD §4 (reasons and alternatives) and speeds approval.

Common problem

Long booking questionnaires.

Change

6 fields, defaults from last booking, extras behind “+ Receiver contact, reference, notes”.

Effect

Repeat booking in 4 clicks; nothing removed.

Common problem

Confirm dialogs on every action.

Change

Dialogs only for irreversible actions; awards get a 10-minute Undo instead.

Effect

Fewer clicks. Needs a backend rule: award notices to losing carriers wait 10 minutes. Not in the BRD.

Common problem

Web and WhatsApp drift apart.

Change

Approvals are one object shown in both; acting in one clears the other.

Effect

No double approvals. Matches the bot-first architecture.

Common problem

Masters hidden in a Settings maze.

Change

One menu item per role with tabs; first-time setup links straight to each tab.

Effect

Navigation stays one level deep.

Implementation readiness

Fits the repo's Next.js 14 + Tailwind stack as is

  • Tokens: colours, radii and spacing from the design system go into tailwind.config.js theme.extend.
  • Fonts: Inter and Space Grotesk via next/font/google.
  • Icons: lucide-react (2 px line icons).
  • Components (about 14): Button, Chip, Input, Select, Combobox, Table, Tabs, Card, Toast, Dialog, Drawer, Segmented, Stepper, EmptyState.
  • Data: status → chip tone map lives next to src/shared/trip-status.ts so web and bot use the same wording.
  • Junior can build: design tokens, Button/Chip/Input/Table/Tabs, Masters tabs, Reports page, Trips list.
  • Lead builds: Approvals (shared with bot), trip task panels, award Undo rule, booking parse.
  • Before build: confirm the GST line on invoices with accounts, and test the screens and colours with 3–5 real users on their own phones and office screens.
  • Still out of scope: vendor (hired truck) screens, deferred from Release 1.
  • Limitation: sample data is illustrative, not from real lanes or carriers.
